# 成书工作流（P4）方案 —— "把书当工程项目做"

> 立项：2026-09-03 用户拍板。方法论依据为用户提供的三阶段框架：
> **① 前期·骨架与地基 → ② 中期·填充与过渡 → ③ 后期·升华打磨交付**。
> 产品目标：让墨池在每一阶段以"工程助理"姿态帮用户顺利推进，直到整书落地。

## 架构判断（用户确认口径）
在现有骨架上**长出"创作项目编排层"**，不做大推翻：
- 复用：works/volumes/chapters（书容器）、work_lore（设定档案）、AI 面板（大纲/角色/续写/润色/诊断/摘要）、灵感馆（素材）、写作统计、整书导出。
- 新增三件事：①数据层 book_plan + 大纲树（计划与成果分离）；②UI 立项向导 + 「蓝图/目录/审校」页签群（WriteStudio 只增不改写）；③AI 阶段化上下文编排（prompt_builder/write 端点扩展，不换栈）。

## MVP-1（纵切三阶段最小闭环，先做这个）
1. **立项蓝图**：新建作品先答「一句话命题 Logline + 目标读者 + 类型 + 目标字数」→ 落库 book_plan；
2. **三级目录草案**：AI 按 type 生成 卷/章/节 大纲 + 每章 beats（核心事件）+ 钩子，保存到大纲树，可手动增删改；
3. **分章任务卡写作**：选择一章 → 写作台注入{本章目标/beats/钩子/相关设定 work_lore/前情摘要}；"写编分离"（编辑器初稿模式：不打断、收集 [TODO]）；章尾可选"生成过渡钩子"；
4. **三轮审校入口**：①结构审（大纲 vs 正文覆盖/冷点）②逐章润色队列（复用 polish，批量）③校对清单（[TODO] 清零、字数、标点）；
5. **收尾交付**：一键导出整书（已有 export）+ 前言/后记/封面文案的 AI 生成位。

## MVP-1 之后（横向扩展，按序）
- 排期与生产指标：目标字数/每日保底/Deadline → 与热力图/打卡联动进度看板；
- beats 编辑器与"本章任务卡"完整版（含伏笔登记）；
- 伏笔与人物弧光追踪（闭环 Payoff 检查）；
- 术语表/参考文献/封面文案高级版；出版规格检查（字数区间/结构完整性）。

## 工程红线（沿用改造守则）
- 新增数据一律走 schema.sql + conftest 自动重建；开发库以幂等 ALTER/建表方式同步并验证；
- 每步：pytest 全量 + build 绿灯才前进；AI 相关测试 stub 零 token；
- 大纲树/蓝图 JSON 结构字段预留 stage 枚举，便于后续扩展而不迁移。
